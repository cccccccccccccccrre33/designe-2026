# Видеокарточки напитков: план

Версия 0.1 · 17.10.2026 · решение владельца: видео делает **Luma Ray2** (через бакет S3), а **Nova 2 Lite** и **Marengo Embed 3.0** проверяют результат. Эти две модели видео не создают: Nova 2 Lite принимает видео на вход и отвечает текстом, Marengo выдаёт вектора (эмбеддинги).

> Статус: план. Кода генерации видео ещё нет. Реестр моделей уже содержит Luma Ray2 и Marengo (оба выключены, у Luma нет цены), см. `studio/policies/models.json`.

## Что получаем

Из утверждённой фотокарточки напитка студия делает короткий ролик (5 с, петля): лёд, пар, пена, капли ведут себя как в жизни, цвет и форма напитка те же, что на фото и в каталоге меню. Ролик показывается владельцу как «концепт-видео (AI)», а не как съёмка: для запуска по-прежнему готовится шот-лист реальной съёмки (`docs/ARCHITECTURE.md`, раздел 6).

## Конвейер

1. **Исходник.** Фотокарточка напитка (кадр Stable Image Ultra или настоящая фотография) плюс описание внешнего вида из каталога (`drinkTruth`): слои, лёд, пена, посуда.
2. **Видео-бриф.** Агент со зрением (Grok 4.7, запасной Grok 4.6) смотрит фото и пишет промпт движения на английском (у Luma лимит 300 токенов): одно простое действие за клип, например «пена оседает, поднимается пар», «лёд медленно проворачивается». Запреты: рука в кадре, смена напитка, текст, логотипы.
3. **Генерация.** Luma Ray2, `StartAsyncInvoke` в регионе us-west-2: `keyframes.frame0` = фото напитка (старт с реального кадра), `duration: 5s`, `resolution: 720p`, `loop: true`. Результат — MP4 5–50 МБ в бакете S3; ожидание 2–8 минут, студия опрашивает `GetAsyncInvoke`.
4. **Проверка физики (Nova 2 Lite).** Модель смотрит ролик и отвечает JSON по чек-листу с таймкодами: лёд плавает и не проходит сквозь стенку, уровень жидкости не прыгает, пена и пузыри двигаются вверх/оседают правдоподобно, капли и струи идут вниз, форма стакана и цвет напитка не меняются, нет лишних предметов и рук. Видео передаётся ссылкой на S3.
5. **Проверка «тот же напиток» (Marengo).** Эмбеддинг фото (InvokeModel) сравнивается с эмбеддингами сегментов ролика (визуальные, `StartAsyncInvoke`): косинусная близость падает, если напиток «уплыл» (другой цвет, другая посуда). Marengo физику не оценивает — только сходство.
6. **Решение кодом.** Порог по чек-листу и по сходству; не прошёл — до 2 перегенераций с исправленным промптом (в пределах бюджета на видео), потом пауза с объяснением. Владельцу уходит только прошедший ролик (как и с экранами: черновики не отправляются).

## Что нужно доработать в коде

- Подпись запросов AWS Signature V4 для S3 (чтение результата). Ключ Bedrock API (bearer) работает только для Bedrock, S3 он не читает.
- `StartAsyncInvoke` / `GetAsyncInvoke` для Luma и Marengo; Converse с видео-блоком для Nova 2 Lite.
- Конвейер видео (бриф → генерация → проверки → решение), учёт расходов (категория `video` есть в реестре бюджета), карточка в Telegram, команда `check-video` для проверки доступа.
- Роль «видео-арт-директор» уже описана (`video-motion-art-director`); добавить её чек-лист физики в базу знаний (`knowledge/methods/beverage-physics.md` уже есть).
- Тесты на сценарных моделях и поддельном S3.

## Что нужно сделать в AWS (владелец)

Регионы: **Luma Ray2 — только us-west-2 (Орегон)**; **Marengo (видео) — только us-east-1 (Сев. Виргиния)**, Ирландия или Сеул. Бакет S3 должен быть в том же регионе, что и вызов модели. Поэтому этап 1 (Luma + Nova 2 Lite) — один бакет в us-west-2; этап 2 (Marengo) — второй бакет в us-east-1.

### Этап 1: Luma Ray2 + Nova 2 Lite

1. **Доступ к моделям.** Консоль Bedrock (us-west-2) → каталог моделей: Luma AI Ray 2 и Amazon Nova 2 Lite. Если консоль просит включить доступ или заполнить форму, включить.
2. **Бакет S3** в us-west-2, например `drivekava-studio-video-<номер аккаунта>`: Block Public Access включён, шифрование по умолчанию (SSE-S3), правило жизненного цикла — удалять объекты через 14 дней.
3. **Пользователь IAM** `studio-video` только с нужными правами (политика ниже). Создать ему ключ доступа (Application running outside AWS).
4. **Секреты GitHub** (Settings → Secrets and variables → Actions), значения вводить только в GitHub, не в чат:
   - Secrets: `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`;
   - Variables: `STUDIO_VIDEO_BUCKET` (имя бакета), `AWS_ACCOUNT_ID` (12 цифр; нужен как `bucketOwner`).
5. **Защита расходов.** AWS Budgets с оповещением (например, на 50% и 80% месячного лимита) и проверка квот Luma в Service Quotas.
6. Написать мне имя бакета и номер аккаунта (это не секреты), цену Luma Ray2 со страницы цен Bedrock за секунду видео (в реестре цены нет, без цены модель не вызывается).

Политика IAM (шаблон, перед применением сверим с текущей справкой AWS; `ACCOUNT` и `BUCKET` заменить):

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["bedrock:InvokeModel"],
      "Resource": [
        "arn:aws:bedrock:us-west-2::foundation-model/luma.ray-v2:0",
        "arn:aws:bedrock:us-west-2:ACCOUNT:async-invoke/*"
      ]
    },
    {
      "Effect": "Allow",
      "Action": ["bedrock:GetAsyncInvoke", "bedrock:ListAsyncInvokes"],
      "Resource": "*"
    },
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject", "s3:ListBucket"],
      "Resource": ["arn:aws:s3:::BUCKET", "arn:aws:s3:::BUCKET/*"]
    }
  ]
}
```

### Этап 2: Marengo Embed 3.0

1. Консоль Bedrock в **us-east-1**: включить TwelveLabs Marengo Embed 3.0.
2. Второй бакет в us-east-1 (те же настройки, что выше); в политику добавить модель `twelvelabs.marengo-embed-3-0-v1:0` и этот бакет. Студия копирует готовый ролик в него для проверки.
3. Переменная `STUDIO_VIDEO_BUCKET_EAST` (имя второго бакета).

### Безопасность

Репозиторий публичный: ключи AWS хранятся только как секреты GitHub (в запуски из чужих форков они не передаются). Права пользователя `studio-video` ограничены этими моделями и этим бакетом. Позже можно заменить долгоживущий ключ на вход через OIDC (без ключа в секретах).

## Порядок работ

1. Этап 1 в AWS (владелец) и параллельно код генерации и проверки Nova 2 Lite на сценарных моделях (я).
2. Первый ролик: одна карточка, ручной запуск `check-video`, разбор результата вместе.
3. Подключение к конвейеру карточек напитков, бюджет на видео.
4. Этап 2: Marengo.
