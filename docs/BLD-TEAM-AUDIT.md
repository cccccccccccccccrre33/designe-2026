## Что это за система

Виртуальная инженерная организация на Microsoft `agent-framework` (Python),
модели через Azure AI Foundry или любой OpenAI-совместимый API. Ядро — 4 роли
(CTO, Backend, Product/Frontend, QA/Security) + модератор + «code scout»,
которые спорят о реальных коммитах с доступом к git через инструменты.
Расширенный режим — около 200–600 персон (советы директоров, «Global Elite»,
отряды, исследовательские треки), 14 GitHub Actions по расписанию, реальное
ветвление, тесты и merge.

Объём: 134 файла, крупнейшие — ростеры персон (`agents/global_elite_*.py`
60–125 КБ каждый), `config/models.py` (87 КБ назначений моделей),
`.state/task_board.json` (171 КБ).

## Что сознательно не переносим

| Проблема | Где | Почему плохо для студии | Что вместо |
|---|---|---|---|
| Операционное состояние в JSON-файлах, `git commit && git push` в main из каждого запуска | `_common.py` (`curate_knowledge`, `save_notebook_entry`, `record_participation`), `.state/` | Гонки при параллельных запусках, шум в истории, файл доски 171 КБ, состояние теряется при конфликте push | DynamoDB/локальное хранилище для состояния; Git — только для решений через PR |
| Вердикт ищется подстрокой `"РЕШЕНИЕ: APPROVE" in text` | `cto_approval.py` | Любая формулировка ломает логику; «не APPROVE» тоже содержит подстроку | JSON-схемы с валидацией и одной попыткой ремонта |
| Вымышленные биографии персон («18 лет код-ревью в Google», «PhD Caltech, DeepMind») | `review_gate.py`, `engineering_fellows.py`, `global_elite*.py` | Бриф прямо запрещает имитацию реальных людей; выдуманный авторитет не улучшает решения | Профили из методов, критериев и источников с тирами достоверности |
| Сотни персон и 14 расписаний «чтобы компания ощущалась живой» | `.github/workflows/*`, `fair_sample` | Расходы без результата; бриф требует подключать только нужных | Кастинг по задаче, недельный аудит с квотой |
| Учёт затрат только через лимит сообщений | `discussion.py` | Нет денег, токенов, лимитов на день и месяц | Ledger с резервированием и отчётом |
| Жёстко вписанные имена моделей с историей замен в комментариях | `config/models.py` | Дрейф назначений, ручной контроль | Реестр моделей + назначения по результатам eval |
| GitHub Actions как рантайм (таймаут 40 минут, нет постоянного вебхука) | `.github/workflows/*` | Нельзя ждать ответа владельца днями и принимать вебхук Telegram | Step Functions + Lambda; Actions — только CI |
