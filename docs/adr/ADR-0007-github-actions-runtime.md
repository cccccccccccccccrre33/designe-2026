# ADR-0007: Студия работает в GitHub Actions, только днём

Статус: принято · 15.10.2026 · заменяет облачную часть этапа 5 (Step Functions,
DynamoDB, S3, AgentCore) как основной способ запуска

## Решение
Студия запускается workflow `.github/workflows/studio.yml` в репозитории designe-2026:

- **Расписание.** Сессия каждые 20 минут днём (cron `7,27,47 5-20 * * *` UTC; с 16.10.2026 — GitHub пропускал часть ежечасных запусков). Точные рабочие
  часы — в `studio/policies/schedule.json`: 08:00–23:00 по Киеву, переход на летнее
  время учитывает код. Вне часов сессия выходит за секунды и не вызывает модели.
- **Сессия** (`npm run studio -- actions-session`, до 50 минут): восстановить
  состояние → продолжить начатое → слушать Telegram владельца и вести очередь →
  сохранять состояние каждые 5 минут и в конце.
- **Ночная остановка.** За 5 минут до конца рабочего дня новые шаги не начинаются:
  `StepJournal` бросает `StopRequested`, инициатива встаёт на паузу `schedule` без
  сообщения владельцу и утром продолжается с того же шага — сделанные шаги не
  оплачиваются второй раз. Задача, присланная ночью, принимается и начинается утром.
- **Состояние** (`.studio-data` и файлы, которые студия пишет в `studio/`) хранится
  в ветке `studio-state`: один коммит без истории, каждый файл зашифрован
  AES-256-GCM ключом из секрета `STUDIO_STATE_KEY`, имена скрыты хэшами. Запись —
  `--force-with-lease` на коммит, с которого восстановились. Если ветка есть, но её
  не удалось прочитать или расшифровать, сессия не стартует.
- **Файлы студии в `studio/`** (предпочтения, решения, версии) переносятся между
  машинами; если тот же файл за это время изменился в `main`, побеждает `main`.
- **Управление владельцем:** переменная репозитория `STUDIO_ENABLED=off` или кнопка
  Disable workflow — полная остановка; Run workflow — запуск сейчас, с задачей и
  (галочкой) вне рабочих часов; `/pause` и `/resume` в Telegram — флаг сохраняется в
  состоянии; сводка каждого запуска — на странице запуска в Actions.

## Почему
- Владелец хочет, чтобы всё было «под рукой» и под контролем, а не в отдельном
  облаке. Репозиторий, запуски, логи, секреты и выключатель — в одном месте.
- Ночью модели не вызываются: деньги тратятся только в рабочие часы, а дневной и
  месячный лимиты бюджета (`budget.json`) продолжают действовать.
- Для публичного репозитория стандартные раннеры GitHub Actions бесплатны и без
  лимита минут. Поэтому репозиторий остаётся публичным, а состояние — зашифрованным.
- Код студии уже был устойчивым к перезапуску (журнал шагов, outbox, идемпотентные
  решения, ADR-0003) — сессиям по часу это и нужно.

## Цена решения
- Бот отвечает, пока идёт сессия. Между сессиями (несколько минут в час) и при
  задержках cron у GitHub сообщение обработается в следующей сессии; Telegram
  хранит необработанные сообщения 24 часа. Ночью бот молчит до 08:00.
- Расписание GitHub бывает неточным (задержки, пропуски в часы пик).
- В публичном репозитории GitHub отключает расписание после 60 дней без активности
  в репозитории — придёт письмо, включается кнопкой во вкладке Actions.
- PR, созданные встроенным `GITHUB_TOKEN`, не запускают другие workflow: проверка CI
  на PR версий дизайна не стартует сама. Версии дизайна — это `studio/`, а не код.
- Если репозиторий сделать приватным, бесплатных минут (2000 в месяц) не хватит на
  сессии весь день — тогда сократить часы или длительность в `schedule.json`.

## Отклонённые варианты
- **AWS Step Functions + Lambda + DynamoDB** (этап 5 исходного плана) — больше
  инфраструктуры, IAM и отдельный счёт; черновик остаётся в `infra/` на случай, если
  понадобится работа 24/7 или мгновенный ответ бота.
- **Состояние в кэше Actions или артефактах** — кэш вытесняется через 7 дней без
  обращений, артефакты живут до 90 дней и неудобны для «последней версии».
- **Отдельный приватный репозиторий для состояния** — нужен дополнительный токен
  владельца; шифрование в той же репе проще и не требует новых прав.
